# 手动测试矩阵

自动化测试只覆盖 native 发送端的协议单元测试（`airplay2-sender-cpp/test/`）。
App 层的行为必须在真机上按下面的表逐条过一遍，尤其是**静音的归属规则**。

## 环境

- 一台 arm64 Android 10+ 手机
- 一台 AirPlay 2 接收器（HomePod / Sonos / Apple TV），与手机同一 Wi-Fi
- 打开设置里的 "Keep a log"，便于失败时导出日志定位

## A. 投屏主流程

| ID | 步骤 | 期望 |
|---|---|---|
| A1 | 地址框为空 | "Start casting" 置灰 |
| A2 | 点 "Find speakers (mDNS)" | 15 s 内列出扬声器；点一行回填 IP 并可开始 |
| A3 | 手输 `IP:端口` | 同样可开始 |
| A4 | 点 Start casting → 授权同意 | 按钮变 "Stop casting"，音箱出声，状态显示 `casting to …` |
| A5 | 投屏中按音量键 | **接收器**音量变化，手机音量不变，诊断行/通知同步 |
| A6 | 通知栏 +/− / 静音按钮 | 同上；静音按钮对应接收器 0% |
| A7 | 系统音量面板 / 锁屏拖动 | 接收器音量跟随；面板里只有**一个** "AirCast" |
| A8 | 滑到 0% 再滑回 | 恢复为静音前的值 |

## B. 静音归属（**核心回归项，见 PITFALLS #1–#6**）

| ID | 步骤 | 期望 |
|---|---|---|
| B1 | 点 Start casting | 手机**立即**静音（在授权弹窗出现之前） |
| B2 | 授权弹窗点右上角 X / 取消 | 手机音量**恢复**；**侧边不出现音量条** |
| B3 | 再来一次，点弹窗**外部**让它消失 | 手机**保持静音**；**不出现音量条**；界面可点 Unmute phone 恢复 |
| B4 | 正常投屏后，通知栏点停止 | 手机**保持静音**；**不出现音量条**；Unmute phone 可恢复 |
| B5 | 投屏后回主界面点 Stop casting | 手机音量**恢复**；不出现音量条 |
| B6 | 投屏中在界面任意位置乱点 | 不应有任何音量变化、不应弹音量条 |
| B7 | 投屏中切到别的应用再切回 | 静音被**重申**（手机保持静音），不弹音量条 |
| B8 | 手机投屏前本来就是静音 → 投屏 → 停止 | 不会凭空恢复出一个音量；日志出现 "no volume recorded" |
| B9 | 连续快速开始/停止多次 | 不出现双份采集、音量不跳变、音量面板无重复条目 |

> 判定 B2/B3/B5 时请**盯着屏幕侧边**：出现过一次系统音量条即为不合格。
> 失败时导出日志，看 `mute` 行里的写入结果与来源。

## C. 音频内容

| ID | 步骤 | 期望 |
|---|---|---|
| C1 | 用 A 应用播放音乐，开始投屏 | 声音从音箱出来 |
| C2 | 换 B 应用（另一个音乐/视频 App）播放 | 同样被转发（当前按 usage 过滤，**这是预期**） |
| C3 | 播放 DRM 内容（Netflix 等） | 静音（系统禁止捕获） |
| C4 | 暂停播放再恢复 | 无长时间静音/爆音 |
| C5 | 连续播放 ≥ 10 min | 不断流（若约 30 s 掉线，检查 event 通道密钥补丁是否还在） |

## D. 延迟与设置

| ID | 步骤 | 期望 |
|---|---|---|
| D1 | 投屏中把延迟从 2.0 s 改到 0.5 s | 本次**无变化**（预期） |
| D2 | 停止再开始投屏 | 延迟明显变短（0.5 s vs 2.0 s，听感可辨） |
| D3 | 延迟拖到最低 0.25 s | 允许；网络差时可能卡顿 |
| D4 | 音量步长改 10% 后按音量键 | 一次跳 10% |
| D5 | 关闭 "Keep a log" | 级别/查看/导出三行隐藏 |
| D6 | 全新安装后首次打开 | 滑块显示 **10%** |
| D7 | 音量拖到 20% → 后台划掉应用 → 重新打开 | 滑块显示 **20%**（不是 10%） |

## E. 异常与恢复

| ID | 步骤 | 期望 |
|---|---|---|
| E1 | 投屏中在系统投屏浮层点 "Stop now" | 服务随之停止，通知消失 |
| E2 | 投屏中关掉 Wi-Fi | 不崩；停止后重新开始可恢复 |
| E3 | 投屏中旋转屏幕 | 界面状态与服务一致（不会显示 idle） |
| E4 | 投屏中杀进程再打开 | 显示 idle；遗留静音由 Unmute phone 处理 |
| E5 | 接收器断电再上电 | 需手动停/开（当前不自动重连） |

## 回归优先级

改动静音相关代码后 **B 组全部必跑**；改 native 后跑 A + C5；改设置后跑 D。
