# 后续规划

按优先级排列，每条都写清"要做什么 / 为什么现在没做 / 代价与坑"。前一条是用户已明确的
需求，其余供参考。

---

## P1. 只转发指定应用（用户已提出）

**目标**：让用户自己选一个应用，只把这个应用的声音转发到音箱。

**为什么现在不是这样**：当前用
`AudioPlaybackCaptureConfiguration.addMatchingUsage(...)` 按**用途**过滤，
任何声明 media/game/unknown 的应用都会一起被捕（见 [PITFALLS.md](PITFALLS.md) #7）。

**做法**：
1. `AudioPlaybackCaptureConfiguration.Builder(mp).addMatchingUid(uid)`，
   过滤条件从 usage 换成 uid（也可 uid + usage 组合）。
2. 在 App 内自己做一个应用选择器（列出可播放媒体的应用 + 图标），记住选择。
3. uid 解析：`PackageManager.getApplicationInfo(pkg, 0).uid`；注意
   **同一 uid 多个包**（sharedUserId、系统应用）会一起被捕获。
4. 默认值建议"全部应用"，保持与现状一致，避免升级后用户觉得"变哑了"。

**已知坑**：
- 系统那个"单个应用 / 整个屏幕"的授权框**不会**把它选中的是哪个应用告诉 App，
  Android 没有对应 API —— 所以**必须自己选**，不能复用系统选择结果。
- 选择器要处理：应用卸载、工作资料（work profile）、无启动图标的应用、
  用户选了不给捕获的应用（DRM/禁捕获）。
- 关闭捕获的应用不会因为 uid 过滤就变得能捕获 —— 过滤只是做减法。

## P2. 断线自动重连

**现状**：接收器掉线后需手动停止再开始（native 侧 `closed` 事件会 `gDone = true`）。

**做法**：native 侧在 `closed` 时不要直接结束，而是回到"待重连"状态，退避重试
（1s/2s/5s/10s）重建 RTSP 会话；投屏授权（`MediaProjection`）仍然有效，不必重新弹窗。

**坑**：重新握手意味着 `SETUP` 会重发一次 —— 正好可以顺带把**新的延迟值**应用上
（见 P3）。若重连失败要给出明确状态，不能静默。

---

## P3. 延迟实时生效

**现状**：延迟只在会话开始时固化（[PITFALLS.md](PITFALLS.md) #8），设置页如实写"下次生效"。

**选项**：
- **A（推荐）**：维持现状，只把文案与交互做清楚（已在设置页注明）。
- **B**：改延迟时立刻重新握手（断开 → 重新 SETUP）。听感上是短暂断音，代价可控但要处理
  与 P2 重连逻辑的交互。
- 不建议只在本地改 `latency_`：接收器的抖动缓冲窗口是 `SETUP` 时定下的，两侧不一致会
  导致欠载/堆积。

---

## P4. 应用在后台时也让音量键控制音箱

**现状**：音量键只在界面处于前台时被 `MainActivity.onKeyDown` 拦截；隐藏后不再路由。

**做法**：通过 `MediaSession` 接管（`setPlaybackToRemote` 已具备），并借助
`AudioManager.dispatchMediaKeyEvent` / 媒体会话的播放状态让系统把音量键交给会话。
需要处理与其它媒体应用争夺媒体会话的问题。

---

## P5. 多接收器 / 多房间同步

**做法**：native 侧支持多个 `RaopSender` 实例，共用同一个采集源与时间轴锚点，
从而保证多房间同步播放。UI 上把"选择设备"改成多选。

**坑**：多个接收器各自 NTP 对时，锚点必须统一，否则会有几十毫秒级的不同步。

---

## P6. 通知栏快速换设备

在通知里加"设备"动作，弹出已发现设备列表（复用 `AirplayDiscovery`），
切换等同于停 + 起（保留 P2 之后可以更顺滑）。

---

## P7. 采集失败的可诊断化

**现状**：`AudioRecord` 构造失败只降级到 48 kHz 再失败就 `stopSelf()`，
用户看不到原因。

**做法**：把失败原因写进状态栏与日志（"设备不允许播放捕获"/"被其它投屏占用"等），
并在首次失败时给一次明确引导。

---

## P8. 界面国际化

**现状**：界面文案全英文（避免中文长句在窄屏被截断）。

**做法**：抽出 `strings.xml`，至少中英双语。若做中英双语，注意检查窄屏截断 ——
现有布局是按英文长度调的。

---

## 不建议做的事

- **不要**给手机侧静音加"定时兜底/任意触摸恢复"（[PITFALLS.md](PITFALLS.md) #1–#6）。
- **不要**用 `FLAG_SHOW_UI` 强推音量写入。
- **不要**在投屏中直接改 `latency_` 而不重新握手。
