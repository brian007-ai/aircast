# 功能与行为契约

版本 **1.0.0**。以下"期望行为"都是当前代码的真实行为，改动后请对照
[TESTING.md](TESTING.md) 逐条回归。

## 1. 功能清单

| # | 功能 | 说明 |
|---|---|---|
| F1 | 转发手机音频到 AirPlay 2 | 抓 `AudioPlaybackCapture`，本地转发，无云端 |
| F2 | mDNS 自动发现 | `_airplay._tcp`，15 s 超时；也可手输 `IP` 或 `IP:端口` |
| F3 | 投屏期间把音量键给接收器 | 界面在前台时由 `onKeyDown` 拦截；同时提供 +/− 按钮 |
| F4 | 投屏期间静音手机 | 手机不再和音箱一起响（见 #4 的归属规则） |
| F5 | 接收器音量控制 | 滑块、音量键、通知按钮、系统音量面板/锁屏 |
| F6 | 前台通知 | 标题 `IP · 音量%`，4 个纯图标动作：停止 / − / + / 静音 |
| F7 | 采集诊断 | 实际速率、峰值、读错误数、已发送秒数 |
| F8 | 可导出日志 | 内存环形缓冲，分级、查看、文本分享 |
| F9 | 启动告知弹窗 | 说明"只发本地、不录音不存储"，可勾选不再显示 |
| F10 | 设置 | 延迟、音量步长、日志开关/级别 |

## 2. 行为契约（重点）

### 开始 / 结束

| 场景 | 期望 |
|---|---|
| 地址为空 | "Start casting" 置灰不可点 |
| 点 Start casting | 先弹告知窗（若未勾选过不再显示），然后**立刻静音**，再弹系统授权 |
| 授权同意 | 开始投屏，按钮变 "Stop casting" |
| 授权拒绝 / 取消 | 不投屏，**恢复音量** |
| 点 Stop casting | **恢复音量** → 停服务 |
| 通知栏停止 | 停服务，**恢复音量：否**（保持静音，由 Unmute phone 按钮恢复） |
| 系统收回投屏 | 同上（保持静音） |

### 静音的归属规则（易错，务必按此实现）

| 场景 | 是否自动恢复音量 | 理由 |
|---|---|---|
| 授权弹窗点右上角 X / 取消 | **是** | 有触摸（弹窗返回），写入被接受 |
| 点弹窗外部让它消失 | **否** | 无触摸，写入会被拒；强制写会弹系统音量条 |
| 通知栏停止 | **否** | 同上 |
| 随便点界面任意位置 | **否** | 同上（旧实现有 `onUserInteraction` 兜底，已删） |
| 回到本界面 | **否**（但会**重申静音**） | 重申是"静音"方向，不是恢复 |
| 手动点 Unmute phone | 是 | 按钮触摸是这台设备最稳定接受的写入 |

### 音量 / 其它

| 场景 | 期望 |
|---|---|
| 投屏中按音量键 | 改**接收器**音量，步长 = 设置值，不改手机音量 |
| 通知栏 +/− | 同上 |
| 系统音量面板拖动 | 同上（`VolumeProvider`） |
| 滑块拖到非 0 | 取消"接收器静音"状态（`castMuted`） |
| 投屏前就拖过滑块 | 音量被持久化，投屏开始时用这个值（不会跳回旧值） |
| 改"延迟" | **本次投屏不生效**，下次投屏生效（见 PITFALLS #8） |
| 改"音量步长"/"日志" | 立即生效 |
| 调整音量后关闭 / 后台划掉再打开 | 滑块显示**上次的值**（仅首次安装是 10%） |
| 手机在投屏前本来就静音 | 不记录 `savedVolume`，撤销时只解除 mute 标志，不虚构音量 |
| 任何媒体应用播放 | 都会被转发（按 usage 过滤，不按应用；见 PITFALLS #7） |
| DRM 应用（Netflix 等） | 静音（系统禁止捕获，无解） |

## 3. 设置项一览

存储文件：`SharedPreferences("cast")`，读取集中在
[Settings.java](../app/src/main/java/com/aircast/app/Settings.java)，**读时也会 clamp**。

| key | 范围 | 默认 | 生效时机 |
|---|---|---|---|
| `host` | 字符串（`IP` / `IP:端口`） | 空 | 立即（点击设备行或输入） |
| `volume` | 0–100 | 10（**仅首次安装**） | 立即；改动即持久化，重启 / 后台划掉后仍显示上次的值 |
| `latency_sec` | 0.25–5.00 s，步进 0.05 | 2.0 | **下次投屏** |
| `vol_step` | 1–20 % | 2 | 立即 |
| `log_enabled` | bool | false | 立即 |
| `log_level` | `error`/`warn`/`info`/`debug` | `info` | 立即 |
| `skip_disclosure` | bool | false | 立即 |

## 4. 不支持 / 已知限制

- 每次投屏都要重新授权一次投屏（Android `MediaProjection` 的硬性要求）。
- 接收器中途掉线不会自动重连，需手动停再开。
- 若其它应用占用了媒体会话，音量键可能调到那个应用而非接收器，用界面 +/− 代替。
- 设备实际授予的采集速率可能不是请求值（44.1 kHz vs 48 kHz），代码会读回真实值并对齐。
- 仅 `arm64-v8a`；最低 Android 10（API 29）。
